Java Sockets – TCP und UDP

Grundlagen der Netzwerkprogrammierung mit einem einfachen Rechner-Beispiel

Start Ziel Grundidee TCP UDP Vergleich Übung

Ziel

Auf dieser Seite lernst du die Grundidee von Java Sockets kennen. Sockets ermöglichen es, dass zwei Programme Daten austauschen können – entweder auf demselben Rechner oder über ein Netzwerk.

Dabei werden die beiden Protokolle TCP und UDP gegenübergestellt. Beide können Daten übertragen, funktionieren aber unterschiedlich.

Im Mittelpunkt steht ein kleines Rechner-Beispiel: Ein Client sendet eine Rechenaufgabe an einen Server. Der Server berechnet das Ergebnis und sendet es zurück.

Zuerst wird das Beispiel mit TCP umgesetzt. Danach wird dieselbe Idee mit UDP gezeigt. Dadurch sieht man besser, was am Programm ähnlich bleibt und was sich durch das Protokoll ändert.

1. Grundidee von Sockets

Ein Socket ist eine Kommunikationsschnittstelle. Ein Programm kann über einen Socket Daten senden oder empfangen.

Man kann sich das vereinfacht wie zwei Programme vorstellen, die über eine Leitung miteinander sprechen. Das eine Programm schreibt Daten hinein, das andere Programm liest sie wieder heraus.

In Java befinden sich die wichtigsten Klassen für Netzwerkprogrammierung im Paket java.net. Für den Einstieg sind vor allem diese Klassen wichtig:

  • ServerSocket – wartet bei TCP auf eingehende Verbindungen
  • Socket – stellt bei TCP die Verbindung zwischen Client und Server dar
  • DatagramSocket – sendet und empfängt UDP-Pakete
  • DatagramPacket – enthält die Daten eines UDP-Pakets

Wichtig ist: Einige Methoden warten auf ein Ereignis. Solche Methoden nennt man blockierend. Das Programm bleibt dann an dieser Stelle stehen, bis zum Beispiel ein Client verbunden ist oder Daten empfangen wurden.

2. TCP kurz erklärt

TCP arbeitet verbindungsorientiert: Ein Client verbindet sich mit einem Server. Erst danach werden Daten übertragen.

TCP sorgt dafür, dass Daten zuverlässig und in der richtigen Reihenfolge ankommen. Geht bei der Übertragung ein Paket verloren, versucht TCP die Daten automatisch erneut zu senden. Der Programmierer merkt davon oft nichts. Deshalb eignet sich TCP für Anwendungen, bei denen nichts verloren gehen darf, zum Beispiel Webseiten, Dateiübertragungen oder Datenbankzugriffe. 

ServerSocket serverSocket = new ServerSocket(5000);
Socket socket = serverSocket.accept();

Der Server öffnet den Port 5000 und wartet mit accept() auf einen Client. Die Methode blockiert, bis sich ein Client verbindet.

Client-Seite

Socket socket = new Socket("localhost", 5000);

Der Client verbindet sich mit dem Server auf Port 5000. Erst danach können beide Seiten Daten austauschen.

Die Methode accept() wartet auf einen Client. Während dieser Zeit blockiert das Programm. Das bedeutet: Die nächste Codezeile wird erst ausgeführt, wenn sich ein Client verbindet.

Sobald ein Client verbunden ist, liefert accept() ein Socket-Objekt zurück. Über dieses Socket können Server und Client anschließend Daten austauschen.

3. UDP kurz erklärt

UDP arbeitet verbindungslos. Der Sender baut vorher keine feste Verbindung zum Empfänger auf. Stattdessen wird ein einzelnes Paket an eine Adresse und einen Port geschickt.

UDP ist einfacher und oft schneller als TCP. Dafür gibt es keine Garantie, dass ein Paket wirklich ankommt. Auch die Reihenfolge mehrerer Pakete ist nicht garantiert. 

DatagramSocket socket = new DatagramSocket(5000);
DatagramPacket packet = new DatagramPacket(buffer, buffer.length);
socket.receive(packet);

Der UDP-Server wartet auf ein Paket am Port 5000. Die Methode receive(...) blockiert, bis ein Paket empfangen wurde.

Client-Seite

DatagramPacket packet =
            new DatagramPacket(
                    daten,
                    daten.length,
                    InetAddress.getByName("localhost"),
                    5000
            );
    
    socket.send(packet);

Der Client sendet ein Paket an den Server auf Port 5000. Anders als bei TCP wird dabei keine feste Verbindung aufgebaut.

Die Methode receive(...) wartet auf ein UDP-Paket. Auch diese Methode blockiert. Das Programm läuft also erst weiter, wenn tatsächlich ein Paket empfangen wurde.

4. TCP und UDP im Vergleich

Beide Protokolle können Daten übertragen. Der wichtigste Unterschied ist, ob vorher eine Verbindung aufgebaut wird und ob die Zustellung garantiert ist.

TCP UDP
verbindungsorientiert verbindungslos
Client verbindet sich mit Server Sender verschickt einzelne Pakete
zuverlässig keine Zustellgarantie
Daten kommen geordnet an Pakete können verloren gehen oder später ankommen
gut für Dateiübertragung, Webseiten, Datenbanken gut für Spiele, Streaming, schnelle Sensordaten

Merksatz:
TCP ist zuverlässiger. UDP ist einfacher und schneller, garantiert aber nicht, dass ein Paket wirklich ankommt.

5. Übung: TCP-Rechner

In dieser Übung wird ein einfacher Rechner mit TCP erstellt. Der Client sendet eine Rechenaufgabe an den Server, zum Beispiel 5 + 3. Der Server berechnet das Ergebnis und sendet es zurück.

Wichtig: Starte immer zuerst den Server. Der Server muss bereits warten, bevor sich der Client verbinden kann.

Aufgabe

Erstelle zwei Java-Klassen:

  • CalculatorServer
  • CalculatorClient

Der Ablauf soll so aussehen:

  1. Der Server startet und öffnet Port 5000.
  2. Der Server wartet blockierend auf einen Client.
  3. Der Client verbindet sich mit dem Server.
  4. Der Client sendet eine Rechenaufgabe, zum Beispiel 5 + 3.
  5. Der Server liest die Aufgabe.
  6. Der Server berechnet das Ergebnis.
  7. Der Server sendet das Ergebnis zurück.
  8. Der Client wartet auf die Antwort und gibt sie aus.

Hinweis

Gehe in kleinen Schritten vor. Bei Sockets ist es besonders wichtig zu verstehen, an welcher Stelle ein Programm wartet.

Schritt 1: ServerSocket erzeugen

ServerSocket serverSocket = new ServerSocket(5000);

Damit öffnet der Server den Port 5000. Über diesen Port können Clients später eine Verbindung zum Server herstellen.

Schritt 2: Auf Client warten

Socket socket = serverSocket.accept();

accept() blockiert. Das Programm bleibt an dieser Stelle stehen, bis sich ein Client verbindet. Deshalb sieht es so aus, als würde der Server „warten“.

Schritt 3: Text vom Client empfangen

BufferedReader in = new BufferedReader(
        new InputStreamReader(socket.getInputStream())
);

String aufgabe = in.readLine();

getInputStream() liefert den Eingabestrom des Sockets. Mit InputStreamReader und BufferedReader kann daraus bequem Text gelesen werden.

readLine() liest eine ganze Textzeile. Auch diese Methode blockiert, solange noch keine vollständige Zeile angekommen ist. Eine Zeile ist hier erst vollständig, wenn der Client mit println(...) einen Zeilenumbruch mitsendet.

Schritt 4: Antwort an den Client senden

PrintWriter out = new PrintWriter(socket.getOutputStream(), true);

out.println(ergebnis);

getOutputStream() liefert den Ausgabestrom des Sockets. Mit PrintWriter kann Text an den Client gesendet werden.

Der zweite Parameter true aktiviert autoFlush. Dadurch wird die Antwort nach println(...) sofort gesendet.

Ohne true könnte die Antwort im Puffer bleiben. Dann würde der Client bei readLine() weiter warten, obwohl der Server scheinbar schon geschrieben hat. 

out.println(ergebnis);
out.flush();

flush() leert den Puffer. Erst dadurch werden gepufferte Daten wirklich hinausgeschrieben.

Lösung: TCP-Rechner

Starte zuerst den Server. Danach startest du den Client. Der Server wartet bei accept(), bis sich der Client verbindet.

CalculatorServer.java

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class CalculatorServer {
    public static void main(String[] args) throws Exception {
        try (ServerSocket serverSocket = new ServerSocket(5000)) {
            System.out.println("Server wartet auf Client...");

            try (Socket socket = serverSocket.accept();
                 BufferedReader in = new BufferedReader(
                         new InputStreamReader(socket.getInputStream())
                 );
                 PrintWriter out = new PrintWriter(
                         socket.getOutputStream(),
                         true
                 )) {

                System.out.println("Client verbunden.");

                String aufgabe = in.readLine();
                System.out.println("Empfangen: " + aufgabe);

                int ergebnis = berechne(aufgabe);

                out.println(ergebnis);
                System.out.println("Gesendet: " + ergebnis);
            }
        }
    }

    private static int berechne(String aufgabe) {
        String[] teile = aufgabe.split(" ");

        int zahl1 = Integer.parseInt(teile[0]);
        String operator = teile[1];
        int zahl2 = Integer.parseInt(teile[2]);

        if (operator.equals("+")) {
            return zahl1 + zahl2;
        }

        if (operator.equals("-")) {
            return zahl1 - zahl2;
        }

        if (operator.equals("*")) {
            return zahl1 * zahl2;
        }

        if (operator.equals("/")) {
            return zahl1 / zahl2;
        }

        throw new IllegalArgumentException("Unbekannter Operator: " + operator);
    }
}

Wichtige Stellen im Server

new ServerSocket(5000) öffnet den Port 5000. Der Server kann dadurch Verbindungen auf diesem Port annehmen.

serverSocket.accept() blockiert, bis sich ein Client verbindet. Vorher läuft der Server an dieser Stelle nicht weiter.

in.readLine() blockiert ebenfalls, bis der Client eine vollständige Zeile gesendet hat. Deshalb verwendet der Client später println(...) und nicht nur print(...).

out.println(ergebnis) sendet das Ergebnis als Textzeile zurück. Durch true im PrintWriter wird danach automatisch geflusht.

CalculatorClient.java

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;

public class CalculatorClient {
    public static void main(String[] args) throws Exception {
        try (Socket socket = new Socket("localhost", 5000);
             BufferedReader in = new BufferedReader(
                     new InputStreamReader(socket.getInputStream())
             );
             PrintWriter out = new PrintWriter(
                     socket.getOutputStream(),
                     true
             )) {

            String aufgabe = "5 + 3";

            out.println(aufgabe);

            String antwort = in.readLine();

            System.out.println("Aufgabe: " + aufgabe);
            System.out.println("Ergebnis vom Server: " + antwort);
        }
    }
}

Wichtige Stellen im Client

new Socket("localhost", 5000) baut die Verbindung zum Server auf. localhost bedeutet: Der Server läuft auf demselben Rechner.

out.println(aufgabe) sendet die Rechenaufgabe an den Server. Durch println(...) wird auch ein Zeilenumbruch gesendet. Das ist wichtig, weil der Server mit readLine() auf eine ganze Zeile wartet.

String antwort = in.readLine(); blockiert, bis der Server eine Antwort sendet. Der Client wartet an dieser Stelle also auf Daten vom Server.

Wenn der Server keine Antwort sendet oder die Antwort nicht geflusht wird, bleibt der Client bei readLine() stehen.

Was passiert beim Ausführen?

Der Server wartet zuerst bei accept(). Erst wenn der Client gestartet wird, entsteht die Verbindung.

Danach sendet der Client die Textzeile 5 + 3. Der Server liest diese Zeile mit readLine(), berechnet das Ergebnis und sendet es mit println(...) zurück.

Weil der PrintWriter mit true erzeugt wurde, wird nach println(...) automatisch ein flush() ausgeführt. Die Antwort bleibt also nicht im Puffer liegen.

6. Zusatz: Gleicher Rechner mit UDP

Das gleiche Beispiel kann auch mit UDP umgesetzt werden. Für den Benutzer sieht das Programm fast gleich aus: Der Client sendet 5 + 3 und bekommt normalerweise 8 zurück.

Der technische Unterschied liegt in der Übertragung: Bei TCP gibt es eine Verbindung und Streams. Bei UDP werden einzelne Pakete gesendet und empfangen.

UDP-Variante

Die Rechenlogik ist gleich. Anders ist nur die Art, wie Daten gesendet und empfangen werden.

UdpCalculatorServer.java

import java.net.DatagramPacket;
import java.net.DatagramSocket;

public class UdpCalculatorServer {
    public static void main(String[] args) throws Exception {
        try (DatagramSocket socket = new DatagramSocket(5000)) {
            byte[] buffer = new byte[1024];

            DatagramPacket packet = new DatagramPacket(buffer, buffer.length);

            System.out.println("UDP-Server wartet auf Paket...");
            socket.receive(packet);

            String aufgabe = new String(
                    packet.getData(),
                    0,
                    packet.getLength()
            );

            int ergebnis = berechne(aufgabe);
            byte[] antwort = String.valueOf(ergebnis).getBytes();

            DatagramPacket response = new DatagramPacket(
                    antwort,
                    antwort.length,
                    packet.getAddress(),
                    packet.getPort()
            );

            socket.send(response);
        }
    }

    private static int berechne(String aufgabe) {
        String[] teile = aufgabe.split(" ");

        int zahl1 = Integer.parseInt(teile[0]);
        String operator = teile[1];
        int zahl2 = Integer.parseInt(teile[2]);

        if (operator.equals("+")) {
            return zahl1 + zahl2;
        }

        if (operator.equals("-")) {
            return zahl1 - zahl2;
        }

        if (operator.equals("*")) {
            return zahl1 * zahl2;
        }

        if (operator.equals("/")) {
            return zahl1 / zahl2;
        }

        throw new IllegalArgumentException("Unbekannter Operator: " + operator);
    }
}

UdpCalculatorClient.java

import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;

public class UdpCalculatorClient {
    public static void main(String[] args) throws Exception {
        try (DatagramSocket socket = new DatagramSocket()) {
            String aufgabe = "5 + 3";
            byte[] daten = aufgabe.getBytes();

            DatagramPacket packet = new DatagramPacket(
                    daten,
                    daten.length,
                    InetAddress.getByName("localhost"),
                    5000
            );

            socket.send(packet);

            byte[] buffer = new byte[1024];
            DatagramPacket response = new DatagramPacket(buffer, buffer.length);

            socket.receive(response);

            String antwort = new String(
                    response.getData(),
                    0,
                    response.getLength()
            );

            System.out.println("Aufgabe: " + aufgabe);
            System.out.println("Ergebnis vom Server: " + antwort);
        }
    }
}

Wichtige Stellen im UDP-Programm

Bei UDP gibt es keinen ServerSocket und kein accept(), weil keine feste Verbindung aufgebaut wird.

Der Server wartet mit socket.receive(packet) auf ein Paket. Diese Methode blockiert, bis ein Paket empfangen wurde.

Der Client sendet mit socket.send(packet) ein Paket an localhost und Port 5000.

Danach wartet der Client mit socket.receive(response) auf die Antwort des Servers. Auch diese Methode blockiert, bis ein Antwortpaket empfangen wurde.

Was ist beim UDP-Programm anders?

In diesem kleinen Beispiel liefern TCP und UDP normalerweise dasselbe Ergebnis. Der Client erhält bei beiden Varianten die Antwort des Servers.

Für den Benutzer sieht die Ausgabe daher fast gleich aus: 

Aufgabe: 5 + 3
Ergebnis vom Server: 8

Der Unterschied liegt nicht im Ergebnis, sondern in der Übertragung:

  • TCP baut zuerst eine Verbindung auf.
  • UDP sendet Daten direkt als Datagramme.
  • TCP verwendet Streams wie BufferedReader und PrintWriter.
  • UDP arbeitet mit Byte-Arrays und DatagramPacket.
  • TCP garantiert die Zustellung und Reihenfolge der Daten.
  • UDP garantiert das nicht.

In kleinen lokalen Testprogrammen merkt man diesen Unterschied oft kaum. In größeren Netzwerken oder bei vielen Paketen wird die unterschiedliche Zuverlässigkeit aber wichtig.
