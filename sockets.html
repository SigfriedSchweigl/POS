TCP, UDP, ServerSocket, Socket, DatagramSocket und DatagramPacket

Ziel

Auf dieser Seite lernst du die Grundlagen der Netzwerkprogrammierung mit Java Sockets kennen. Du unterscheidest zwischen TCP und UDP und setzt einfache Client-Server-Programme um.

Die Beispiele sind bewusst klein gehalten. Im Mittelpunkt stehen die Klassen Socket, ServerSocket, DatagramSocket, DatagramPacket und InetAddress aus dem Paket java.net.

1. Grundlagen: Was ist ein Socket?

Ein Socket ist ein Kommunikationsendpunkt. Über diesen Endpunkt kann ein Programm Daten über ein Netzwerk senden oder empfangen.

In Java unterscheidet man vor allem zwischen TCP-Sockets und UDP-Sockets. TCP arbeitet verbindungsorientiert, UDP verbindungslos.

Stelle dir TCP wie ein Telefongespräch vor: Zuerst wird eine Verbindung aufgebaut, danach werden Daten ausgetauscht. UDP ist eher wie eine Postkarte: Sie wird abgeschickt, aber es gibt keine Garantie, dass sie ankommt.

Wichtige Klassen

  • InetAddress: repräsentiert eine IP-Adresse
  • Socket: TCP-Client-Socket
  • ServerSocket: TCP-Server-Socket
  • DatagramSocket: UDP-Socket zum Senden und Empfangen
  • DatagramPacket: UDP-Datenpaket

Beispiel: IP-Adresse ermitteln

import java.net.InetAddress;
import java.net.UnknownHostException;

public class InetAddressExample {
    public static void main(String[] args) throws UnknownHostException {
        InetAddress localhost = InetAddress.getLocalHost();
        InetAddress address = InetAddress.getByName("localhost");

        System.out.println("Localhost: " + localhost.getHostAddress());
        System.out.println("Adresse: " + address.getHostAddress());
    }
}

Merksatz:
InetAddress wird verwendet, wenn ein Programm mit IP-Adressen oder Hostnamen arbeitet.

2. TCP: Echo-Server und Echo-Client

Problem:
Ein Client soll eine Nachricht an einen Server senden. Der Server soll die Nachricht empfangen und wieder zurückschicken.

Bei TCP muss zuerst ein Server gestartet werden. Danach kann sich ein Client mit diesem Server verbinden. 

ServerSocket serverSocket = new ServerSocket(5000);
Socket clientSocket = serverSocket.accept();

Die Methode accept() wartet so lange, bis sich ein Client verbindet. Danach liefert sie ein Socket-Objekt für die Kommunikation mit genau diesem Client.

TCP-Server

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class TcpEchoServer {
    public static void main(String[] args) throws IOException {
        int port = 5000;

        try (ServerSocket serverSocket = new ServerSocket(port)) {
            System.out.println("Server läuft auf Port " + port);
            System.out.println("Warte auf Client...");

            try (Socket clientSocket = serverSocket.accept();
                 BufferedReader in = new BufferedReader(
                         new InputStreamReader(clientSocket.getInputStream()));
                 PrintWriter out = new PrintWriter(
                         clientSocket.getOutputStream(), true)) {

                System.out.println("Client verbunden.");

                String message = in.readLine();
                System.out.println("Empfangen: " + message);

                out.println("Echo: " + message);
            }
        }
    }
}

TCP-Client

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;

public class TcpEchoClient {
    public static void main(String[] args) throws IOException {
        String host = "localhost";
        int port = 5000;

        try (Socket socket = new Socket(host, port);
             BufferedReader in = new BufferedReader(
                     new InputStreamReader(socket.getInputStream()));
             PrintWriter out = new PrintWriter(socket.getOutputStream(), true)) {

            out.println("Hallo Server");

            String response = in.readLine();
            System.out.println("Antwort vom Server: " + response);
        }
    }
}

Ablauf

  1. Zuerst TcpEchoServer starten.
  2. Danach TcpEchoClient starten.
  3. Der Client sendet eine Nachricht.
  4. Der Server gibt die Nachricht als Echo zurück.

Merksatz:
TCP ist zuverlässig und verbindungsorientiert. Deshalb eignet sich TCP gut für Dateiübertragungen, HTTP, SMTP oder Datenbankzugriffe.

3. TCP: Mehrere Nachrichten verarbeiten

Problem:
Der einfache Echo-Server verarbeitet nur eine Nachricht. Nun soll der Server mehrere Nachrichten lesen, bis der Client exit sendet. 

String message;

while ((message = in.readLine()) != null) {
    out.println("Echo: " + message);
}

Verwende eine Schleife. Die Schleife soll beendet werden, wenn der Client den Text exit sendet.

Server mit Schleife

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class TcpLoopServer {
    public static void main(String[] args) throws IOException {
        int port = 5000;

        try (ServerSocket serverSocket = new ServerSocket(port)) {
            System.out.println("Server läuft auf Port " + port);

            try (Socket clientSocket = serverSocket.accept();
                 BufferedReader in = new BufferedReader(
                         new InputStreamReader(clientSocket.getInputStream()));
                 PrintWriter out = new PrintWriter(
                         clientSocket.getOutputStream(), true)) {

                String message;

                while ((message = in.readLine()) != null) {
                    if (message.equalsIgnoreCase("exit")) {
                        out.println("Verbindung wird beendet.");
                        break;
                    }

                    out.println("Echo: " + message);
                }
            }
        }
    }
}

Client mit mehreren Nachrichten

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;

public class TcpLoopClient {
    public static void main(String[] args) throws IOException {
        try (Socket socket = new Socket("localhost", 5000);
             BufferedReader in = new BufferedReader(
                     new InputStreamReader(socket.getInputStream()));
             PrintWriter out = new PrintWriter(socket.getOutputStream(), true)) {

            out.println("Erste Nachricht");
            System.out.println(in.readLine());

            out.println("Zweite Nachricht");
            System.out.println(in.readLine());

            out.println("exit");
            System.out.println(in.readLine());
        }
    }
}

Merksatz:
Bei TCP liest und schreibt man über Streams. Das ähnelt dem Arbeiten mit Dateien.

4. UDP: Datagramm senden und empfangen

Problem:
Ein Client soll eine kurze Nachricht per UDP senden. Der Server soll das Datagramm empfangen und ausgeben.

UDP baut keine Verbindung auf. Jede Nachricht wird als einzelnes Paket verschickt. 

DatagramSocket socket = new DatagramSocket(5001);
DatagramPacket packet = new DatagramPacket(buffer, buffer.length);
socket.receive(packet);

Beim Empfangen wird ein leerer Byte-Puffer vorbereitet. Nach receive(...) enthält das Paket die empfangenen Daten und die Adresse des Absenders.

UDP-Server

import java.io.IOException;
import java.net.DatagramPacket;
import java.net.DatagramSocket;

public class UdpServer {
    public static void main(String[] args) throws IOException {
        int port = 5001;
        byte[] buffer = new byte[1024];

        try (DatagramSocket socket = new DatagramSocket(port)) {
            System.out.println("UDP-Server läuft auf Port " + port);

            DatagramPacket packet = new DatagramPacket(buffer, buffer.length);
            socket.receive(packet);

            String message = new String(
                    packet.getData(),
                    0,
                    packet.getLength()
            );

            System.out.println("Empfangen von "
                    + packet.getAddress().getHostAddress()
                    + ": " + message);
        }
    }
}

UDP-Client

import java.io.IOException;
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.nio.charset.StandardCharsets;

public class UdpClient {
    public static void main(String[] args) throws IOException {
        String message = "Hallo UDP-Server";
        byte[] data = message.getBytes(StandardCharsets.UTF_8);

        InetAddress address = InetAddress.getByName("localhost");
        int port = 5001;

        DatagramPacket packet = new DatagramPacket(
                data,
                data.length,
                address,
                port
        );

        try (DatagramSocket socket = new DatagramSocket()) {
            socket.send(packet);
            System.out.println("Nachricht gesendet.");
        }
    }
}

Merksatz:
UDP ist schnell, aber nicht zuverlässig. Pakete können verloren gehen oder in anderer Reihenfolge ankommen.

5. UDP: Antwort an den Client senden

Problem:
Der UDP-Server soll nicht nur empfangen, sondern auch eine Antwort an den Client zurücksenden.

Die Absenderadresse und der Absenderport stehen nach dem Empfang im empfangenen DatagramPacket. Diese Informationen können für das Antwortpaket verwendet werden.

UDP-Echo-Server

import java.io.IOException;
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.nio.charset.StandardCharsets;

public class UdpEchoServer {
    public static void main(String[] args) throws IOException {
        int port = 5001;
        byte[] buffer = new byte[1024];

        try (DatagramSocket socket = new DatagramSocket(port)) {
            DatagramPacket request = new DatagramPacket(buffer, buffer.length);
            socket.receive(request);

            String message = new String(
                    request.getData(),
                    0,
                    request.getLength(),
                    StandardCharsets.UTF_8
            );

            String responseText = "Echo: " + message;
            byte[] responseData = responseText.getBytes(StandardCharsets.UTF_8);

            DatagramPacket response = new DatagramPacket(
                    responseData,
                    responseData.length,
                    request.getAddress(),
                    request.getPort()
            );

            socket.send(response);
        }
    }
}

UDP-Echo-Client

import java.io.IOException;
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.nio.charset.StandardCharsets;

public class UdpEchoClient {
    public static void main(String[] args) throws IOException {
        InetAddress address = InetAddress.getByName("localhost");
        int port = 5001;

        byte[] data = "Hallo Server".getBytes(StandardCharsets.UTF_8);

        try (DatagramSocket socket = new DatagramSocket()) {
            DatagramPacket request = new DatagramPacket(
                    data,
                    data.length,
                    address,
                    port
            );

            socket.send(request);

            byte[] buffer = new byte[1024];
            DatagramPacket response = new DatagramPacket(buffer, buffer.length);
            socket.receive(response);

            String text = new String(
                    response.getData(),
                    0,
                    response.getLength(),
                    StandardCharsets.UTF_8
            );

            System.out.println("Antwort: " + text);
        }
    }
}

Der Client benötigt beim Empfangen keinen festen Port. Der DatagramSocket erhält automatisch einen freien lokalen Port.

6. Vergleich: TCP oder UDP?

TCP und UDP werden für unterschiedliche Anwendungsfälle verwendet. Die Entscheidung hängt davon ab, ob Zuverlässigkeit oder Geschwindigkeit im Vordergrund steht.

TCP

TCP ist verbindungsorientiert. Vor dem Datenaustausch wird eine Verbindung aufgebaut. Die Daten kommen zuverlässig und in der richtigen Reihenfolge an.

Typische Anwendungen:
HTTP, SMTP, Dateiübertragungen und Datenbankzugriffe.

UDP

UDP ist verbindungslos. Pakete werden ohne vorherigen Verbindungsaufbau gesendet. Dadurch ist UDP schneller, aber nicht zuverlässig.

Typische Anwendungen:
Audio- und Videoübertragung, Spiele, Multicast und andere Anwendungen mit geringer Latenz.

Kurz gesagt

TCP: sicherer, geordnet, verbindungsorientiert.

UDP: schneller, einfacher, verbindungslos.

Aufgabe 1: TCP-Begrüßungsserver

Schreibe einen TCP-Server, der den Namen eines Clients empfängt und mit Hallo Max antwortet.

Lies mit readLine() den Namen ein und schreibe mit println(...) die Antwort zurück. 

String name = in.readLine();
out.println("Hallo " + name);

Aufgabe 2: TCP-Rechner

Der Client sendet zwei Zahlen. Der Server berechnet die Summe und sendet das Ergebnis zurück.

Sende beide Zahlen als Textzeilen. Verwende am Server Integer.parseInt(...) oder Double.parseDouble(...). 

int number1 = Integer.parseInt(in.readLine());
int number2 = Integer.parseInt(in.readLine());

int sum = number1 + number2;

out.println("Summe: " + sum);

Aufgabe 3: UDP-Zeitserver

Der Client sendet eine beliebige Anfrage an den Server. Der Server sendet die aktuelle Uhrzeit zurück.

Verwende LocalTime.now() und sende die Antwort an request.getAddress() und request.getPort(). 

import java.time.LocalTime;

String responseText = "Uhrzeit: " + LocalTime.now();
byte[] responseData = responseText.getBytes(StandardCharsets.UTF_8);

DatagramPacket response = new DatagramPacket(
        responseData,
        responseData.length,
        request.getAddress(),
        request.getPort()
);

socket.send(response);

Aufgabe 4: Begriffe erklären

Erkläre die Begriffe Socket, ServerSocket, DatagramSocket, DatagramPacket und InetAddress in eigenen Worten.

  • Socket: TCP-Endpunkt eines Clients oder Servers.
  • ServerSocket: wartet auf eingehende TCP-Verbindungen.
  • DatagramSocket: sendet und empfängt UDP-Pakete.
  • DatagramPacket: enthält Daten, Zieladresse oder Absenderadresse.
  • InetAddress: repräsentiert eine IP-Adresse oder einen Hostnamen.
