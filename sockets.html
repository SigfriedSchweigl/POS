Java Sockets – TCP und UDP

Netzwerkprogrammierung mit ServerSocket, Socket, DatagramSocket und DatagramPacket

Start Grundlagen TCP UDP Vergleich Übungen

Ziel

Auf dieser Seite lernst du, wie Programme in Java über ein Netzwerk miteinander kommunizieren können. Im Mittelpunkt stehen zwei Varianten: TCP für zuverlässige Verbindungen und UDP für einfache Datagramme.

Die Beispiele sind bewusst klein gehalten. Zuerst geht es darum, den Ablauf zu verstehen: Ein Server wartet, ein Client verbindet sich oder sendet ein Paket, und beide Programme tauschen Daten aus.

1. Grundlagen: Was ist ein Socket?

Ein Socket ist eine Programmierschnittstelle für Netzwerkkommunikation. Man kann sich einen Socket wie eine Verbindungstür zwischen zwei Programmen vorstellen.

In Java liegen die wichtigsten Klassen dafür im Paket java.net.

TCP und UDP kurz erklärt

TCP arbeitet verbindungsorientiert. Vor dem Datenaustausch wird eine Verbindung aufgebaut. Die Daten kommen zuverlässig und in der richtigen Reihenfolge an.

UDP arbeitet verbindungslos. Es werden einzelne Pakete verschickt. Das ist einfach und schnell, aber es gibt keine Garantie, dass ein Paket ankommt.

Typische TCP-Beispiele sind Webzugriffe, E-Mail oder Datenbankverbindungen. Typische UDP-Beispiele sind Echtzeitanwendungen, bei denen Geschwindigkeit wichtiger als vollständige Zustellung ist.

Wichtige Klassen

  • InetAddress: beschreibt eine IP-Adresse oder einen Hostnamen
  • ServerSocket: wartet bei TCP auf eingehende Verbindungen
  • Socket: steht bei TCP für die Verbindung zwischen Client und Server
  • DatagramSocket: sendet oder empfängt UDP-Pakete
  • DatagramPacket: enthält die Daten eines UDP-Pakets

2. TCP: Echo-Server und Echo-Client

Bei TCP gibt es zuerst einen Server. Er öffnet einen Port und wartet auf einen Client. Der Client verbindet sich mit diesem Port. Danach können beide Programme über Streams Daten senden und empfangen.

Ablauf bei TCP

  1. Der Server erzeugt einen ServerSocket.
  2. Der Server wartet mit accept() auf einen Client.
  3. Der Client erzeugt einen Socket und verbindet sich.
  4. Beide Seiten lesen und schreiben über Streams.
  5. Am Ende werden die Ressourcen geschlossen.

Echo-Server

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;

public class EchoServer {
    public static void main(String[] args) throws Exception {
        int port = 5000;

        try (ServerSocket serverSocket = new ServerSocket(port)) {
            System.out.println("Server wartet auf Port " + port);

            try (Socket clientSocket = serverSocket.accept();
                 BufferedReader in = new BufferedReader(
                         new InputStreamReader(clientSocket.getInputStream()));
                 PrintWriter out = new PrintWriter(
                         clientSocket.getOutputStream(), true)) {

                System.out.println("Client verbunden");

                String message = in.readLine();
                System.out.println("Empfangen: " + message);

                out.println("Echo: " + message);
            }
        }
    }
}

Erklärung zum Server

new ServerSocket(port) öffnet den Port 5000. Der Server ist danach unter diesem Port erreichbar.

serverSocket.accept() wartet auf einen Client. Diese Methode blockiert, bis sich wirklich ein Client verbindet.

Das Ergebnis von accept() ist ein normales Socket-Objekt. Über dieses Objekt kommuniziert der Server mit genau diesem Client.

BufferedReader wird verwendet, um Text zeilenweise zu lesen. Deshalb passt dazu auf der anderen Seite println(...).

Der PrintWriter schreibt Text an den Client zurück. Der zweite Parameter true aktiviert autoFlush. Dadurch wird eine Zeile nach println(...) sofort gesendet. 

PrintWriter out = new PrintWriter(clientSocket.getOutputStream(), true);

Ohne true müsste man nach dem Schreiben selbst flush() aufrufen. 

out.println("Echo: " + message);
out.flush();

Echo-Client

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;

public class EchoClient {
    public static void main(String[] args) throws Exception {
        String host = "localhost";
        int port = 5000;

        try (Socket socket = new Socket(host, port);
             BufferedReader in = new BufferedReader(
                     new InputStreamReader(socket.getInputStream()));
             PrintWriter out = new PrintWriter(
                     socket.getOutputStream(), true)) {

            out.println("Hallo Server");

            String response = in.readLine();
            System.out.println("Antwort: " + response);
        }
    }
}

Erklärung zum Client

localhost bedeutet: Der Client verbindet sich mit dem eigenen Computer. Das ist praktisch zum Testen, weil Server und Client auf demselben Rechner laufen können.

new Socket(host, port) baut die Verbindung zum Server auf. Der Port muss mit dem Port des Servers übereinstimmen.

out.println("Hallo Server") sendet eine Zeile an den Server. Weil autoFlush aktiv ist, wird die Zeile sofort übertragen.

in.readLine() wartet auf eine Antwort des Servers. Auch diese Methode blockiert, bis eine Zeile empfangen wurde.

Aufgabe

Erweitere den Echo-Server so, dass der Client mehrere Nachrichten senden kann. Erst wenn der Client ende sendet, soll die Verbindung beendet werden.

Hinweis

String message;

while ((message = in.readLine()) != null) {
    if (message.equalsIgnoreCase("ende")) {
        break;
    }

    out.println("Echo: " + message);
}

3. UDP: Nachricht senden und empfangen

UDP funktioniert anders als TCP. Es wird keine feste Verbindung aufgebaut. Stattdessen wird eine Nachricht als Datagramm verschickt.

Der Empfänger muss nur auf einem Port warten. Der Sender schickt ein Paket an eine Adresse und einen Port.

UDP-Empfänger

import java.net.DatagramPacket;
import java.net.DatagramSocket;

public class UdpReceiver {
    public static void main(String[] args) throws Exception {
        int port = 6000;
        byte[] buffer = new byte[1024];

        try (DatagramSocket socket = new DatagramSocket(port)) {
            System.out.println("UDP-Empfänger wartet auf Port " + port);

            DatagramPacket packet = new DatagramPacket(buffer, buffer.length);
            socket.receive(packet);

            String message = new String(
                    packet.getData(),
                    0,
                    packet.getLength()
            );

            System.out.println("Empfangen: " + message);
        }
    }
}

Erklärung zum UDP-Empfänger

new DatagramSocket(port) öffnet einen UDP-Socket auf Port 6000. Dieser Socket wartet auf eingehende Pakete.

Das Bytearray buffer ist der Speicherplatz für die empfangenen Daten. UDP arbeitet nicht direkt mit Strings, sondern mit Bytes.

socket.receive(packet) wartet, bis ein Paket eintrifft. Danach enthält packet die Daten, aber auch Informationen über den Absender.

packet.getLength() ist wichtig, weil der Buffer größer sein kann als die tatsächlich empfangene Nachricht.

UDP-Sender

import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;

public class UdpSender {
    public static void main(String[] args) throws Exception {
        String message = "Hallo UDP";
        byte[] data = message.getBytes();

        InetAddress address = InetAddress.getByName("localhost");
        int port = 6000;

        try (DatagramSocket socket = new DatagramSocket()) {
            DatagramPacket packet = new DatagramPacket(
                    data,
                    data.length,
                    address,
                    port
            );

            socket.send(packet);
            System.out.println("Nachricht gesendet");
        }
    }
}

Erklärung zum UDP-Sender

message.getBytes() wandelt den String in ein Bytearray um. Das ist notwendig, weil ein DatagramPacket Bytes verschickt.

InetAddress.getByName("localhost") liefert die Adresse des Zielrechners. Beim Testen ist das wieder der eigene Computer.

Beim Sender reicht new DatagramSocket(). Es muss kein fixer lokaler Port angegeben werden, weil der Sender nur ein Paket verschickt.

Das DatagramPacket enthält vier Dinge: Daten, Länge, Zieladresse und Zielport.

Aufgabe

Ändere den UDP-Sender so, dass er drei verschiedene Nachrichten sendet. Starte zuerst den Empfänger und danach den Sender.

Hinweis

String[] messages = { "Hallo", "Wie geht es?", "Ende" };

for (String message : messages) {
    byte[] data = message.getBytes();

    DatagramPacket packet = new DatagramPacket(
            data,
            data.length,
            address,
            port
    );

    socket.send(packet);
}

4. Vergleich: TCP oder UDP?

Die wichtigste Entscheidung lautet: Brauche ich eine zuverlässige Verbindung oder reicht das schnelle Verschicken einzelner Pakete?

TCP

TCP verwendet man, wenn Daten vollständig und in der richtigen Reihenfolge ankommen müssen.

  • verbindungsorientiert
  • zuverlässig
  • streambasiert
  • geeignet für HTTP, E-Mail, Datenbankzugriffe

UDP

UDP verwendet man, wenn eine einfache und schnelle Übertragung wichtiger ist als garantierte Zustellung.

  • verbindungslos
  • keine Zustellgarantie
  • paketbasiert
  • geeignet für Audio, Video, Spiele oder Broadcasts

Merksatz

TCP: sicherer und geordneter Datenaustausch.
UDP: einfache und schnelle Paketübertragung.

5. Übungen

Bearbeite die Übungen schrittweise. Teste immer zuerst auf localhost, damit Server und Client auf demselben Rechner laufen können.

Übung 1: TCP-Begrüßungsserver

Erstelle einen TCP-Server, der eine Nachricht vom Client empfängt und mit Willkommen, ... antwortet. 

String name = in.readLine();
out.println("Willkommen, " + name);

Übung 2: TCP-Rechner

Der Client sendet zwei Zahlen. Der Server addiert sie und sendet das Ergebnis zurück. 

int a = Integer.parseInt(in.readLine());
int b = Integer.parseInt(in.readLine());

out.println(a + b);

Übung 3: UDP-Statusmeldung

Ein UDP-Sender schickt die Nachricht System läuft an einen Empfänger. Der Empfänger gibt die Nachricht auf der Konsole aus.

Verwende beim Empfänger DatagramSocket(port) und beim Sender DatagramPacket(data, data.length, address, port).

Übung 4: Fehler beobachten

Starte den TCP-Client, ohne dass der Server läuft. Beobachte die Fehlermeldung. Erkläre danach, warum der Fehler entsteht.

Der Client versucht, sich mit einem Server auf einem bestimmten Port zu verbinden. Wenn dort kein Server wartet, kann keine TCP-Verbindung aufgebaut werden.
