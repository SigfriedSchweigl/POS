Design Patterns – Übungen mit Lösungen

Interaktive Übungen zu wichtigen Design Patterns in Java

Start Singleton Simple Factory Factory Method Abstract Factory Adapter

Ziel

Design Patterns sind bewährte Lösungsansätze für häufige Probleme in der Softwareentwicklung.

Auf dieser Seite werden wichtige Patterns anhand einfacher Java-Beispiele erklärt.

Zu jeder Aufgabe gibt es Hinweise und Musterlösungen.

1. Singleton Pattern

Aufgabe:
Warum kann diese Klasse problematisch sein? 

class DatabaseConfig {

    private String url = "jdbc:h2:./db/school";

    public String getUrl() {
        return url;
    }
}

Überlege, was passiert, wenn mehrere Objekte von DatabaseConfig erzeugt werden.

Lösung

Ohne Singleton könnten mehrere unterschiedliche Konfigurationsobjekte entstehen. 

DatabaseConfig config1 = new DatabaseConfig();
DatabaseConfig config2 = new DatabaseConfig();

Dadurch könnten verschiedene Teile des Programms mit unterschiedlichen Datenbankeinstellungen arbeiten.

Das Singleton Pattern stellt sicher, dass nur ein einziges Objekt existiert. 

class DatabaseConfig {

    private static final DatabaseConfig INSTANCE =
            new DatabaseConfig();

    private String url = "jdbc:h2:./db/school";

    private DatabaseConfig() {
    }

    public static DatabaseConfig getInstance() {
        return INSTANCE;
    }

    public String getUrl() {
        return url;
    }
}

Auf das Objekt wird nun zentral zugegriffen: 

DatabaseConfig config =
        DatabaseConfig.getInstance();

2. Simple Factory

Aufgabe:
Warum ist die Objekterzeugung hier ungünstig? 

class Main {

    public static void main(String[] args) {

        String type = "teacher";

        if (type.equals("teacher")) {
            User user = new Teacher();
            user.printRole();
        }

        if (type.equals("student")) {
            User user = new Student();
            user.printRole();
        }
    }
}

Die Objekterzeugung steht direkt in der Programmlogik.

Diese Logik kann ausgelagert werden.

Lösung

Die Factory übernimmt die Objekterzeugung an einer zentralen Stelle. 

interface User {
    void printRole();
}

class Teacher implements User {

    public void printRole() {
        System.out.println("Ich bin Lehrer.");
    }
}

class Student implements User {

    public void printRole() {
        System.out.println("Ich bin Schüler.");
    }
}

class UserFactory {

    public static User createUser(String type) {

        if (type.equals("teacher")) {
            return new Teacher();
        }

        if (type.equals("student")) {
            return new Student();
        }

        throw new IllegalArgumentException();
    }
}

Verwendung: 

User user =
        UserFactory.createUser("teacher");

user.printRole();

3. Factory Method Pattern

Aufgabe:
Wie kann man vermeiden, dass die Klasse direkt konkrete Repositorys erzeugt? 

class Application {

    public void run() {

        StudentRepository repository =
                new H2StudentRepository();

        repository.findAll();
    }
}

Die Klasse hängt direkt von H2StudentRepository ab.

Die Objekterzeugung kann an Unterklassen delegiert werden.

Lösung

Die Oberklasse definiert den allgemeinen Ablauf.

Unterklassen entscheiden, welches konkrete Objekt erzeugt wird. 

interface StudentRepository {
    void findAll();
}

class H2StudentRepository
        implements StudentRepository {

    public void findAll() {
        System.out.println("H2 Repository");
    }
}

class MySqlStudentRepository
        implements StudentRepository {

    public void findAll() {
        System.out.println("MySQL Repository");
    }
}

abstract class Application {

    public void run() {

        StudentRepository repository =
                createRepository();

        repository.findAll();
    }

    protected abstract
    StudentRepository createRepository();
}

class H2Application extends Application {

    protected StudentRepository
    createRepository() {

        return new H2StudentRepository();
    }
}

class MySqlApplication extends Application {

    protected StudentRepository
    createRepository() {

        return new MySqlStudentRepository();
    }
}

Verwendung

public class Main {

    public static void main(String[] args) {

        Application app =
                new H2Application();

        app.run();
    }
}

Obwohl die Variable den Typ Application hat, steckt intern ein H2Application-Objekt darin.

Deshalb wird automatisch diese Methode verwendet: 

protected StudentRepository
createRepository() {

    return new H2StudentRepository();
}

Merksatz:
Die Oberklasse definiert den Ablauf, die Unterklasse liefert das konkrete Objekt.

4. Abstract Factory Pattern

Aufgabe:
Warum wird der Code unübersichtlich, wenn mehrere zusammengehörige Objekte erzeugt werden müssen? 

StudentRepository studentRepository =
        new H2StudentRepository();

TeacherRepository teacherRepository =
        new H2TeacherRepository();

Was passiert, wenn von H2 auf MySQL gewechselt wird?

Dann müssen mehrere Stellen angepasst werden.

Lösung

Die Abstract Factory erzeugt zusammengehörige Objektfamilien. 

interface StudentRepository {
    void findAll();
}

interface TeacherRepository {
    void findAll();
}

class H2StudentRepository
        implements StudentRepository {

    public void findAll() {
        System.out.println("H2 Student");
    }
}

class H2TeacherRepository
        implements TeacherRepository {

    public void findAll() {
        System.out.println("H2 Teacher");
    }
}

class MySqlStudentRepository
        implements StudentRepository {

    public void findAll() {
        System.out.println("MySQL Student");
    }
}

class MySqlTeacherRepository
        implements TeacherRepository {

    public void findAll() {
        System.out.println("MySQL Teacher");
    }
}

interface RepositoryFactory {

    StudentRepository
    createStudentRepository();

    TeacherRepository
    createTeacherRepository();
}

class H2RepositoryFactory
        implements RepositoryFactory {

    public StudentRepository
    createStudentRepository() {

        return new H2StudentRepository();
    }

    public TeacherRepository
    createTeacherRepository() {

        return new H2TeacherRepository();
    }
}

class MySqlRepositoryFactory
        implements RepositoryFactory {

    public StudentRepository
    createStudentRepository() {

        return new MySqlStudentRepository();
    }

    public TeacherRepository
    createTeacherRepository() {

        return new MySqlTeacherRepository();
    }
}

Verwendung

public class Main {

    public static void main(String[] args) {

        RepositoryFactory factory =
                new H2RepositoryFactory();

        StudentRepository studentRepository =
                factory.createStudentRepository();

        TeacherRepository teacherRepository =
                factory.createTeacherRepository();

        studentRepository.findAll();
        teacherRepository.findAll();
    }
}

Durch den Austausch der Factory kann die gesamte Objektfamilie gewechselt werden. 

RepositoryFactory factory =
        new MySqlRepositoryFactory();

Dadurch muss der restliche Code nicht angepasst werden.

5. Adapter Pattern

Aufgabe:
Wie kann eine alte Klasse weiterverwendet werden, obwohl sie nicht zum neuen Interface passt? 

class OldCsvStudentReader {

    public String[] readStudentsFromCsv() {

        return new String[] {
                "Max",
                "Anna",
                "Sara"
        };
    }
}

interface StudentReader {

    List<String> readStudents();
}

Die alte Klasse liefert ein Array zurück.

Das neue Interface erwartet aber eine List<String>.

Lösung

Der Adapter übersetzt zwischen alter Klasse und neuem Interface. 

import java.util.Arrays;
import java.util.List;

class OldCsvStudentReader {

    public String[] readStudentsFromCsv() {

        return new String[] {
                "Max",
                "Anna",
                "Sara"
        };
    }
}

interface StudentReader {

    List<String> readStudents();
}

class CsvStudentReaderAdapter
        implements StudentReader {

    private OldCsvStudentReader oldReader;

    public CsvStudentReaderAdapter(
            OldCsvStudentReader oldReader) {

        this.oldReader = oldReader;
    }

    public List<String> readStudents() {

        return Arrays.asList(
                oldReader.readStudentsFromCsv()
        );
    }
}

Verwendung

public class Main {

    public static void main(String[] args) {

        OldCsvStudentReader oldReader =
                new OldCsvStudentReader();

        StudentReader reader =
                new CsvStudentReaderAdapter(oldReader);

        System.out.println(
                reader.readStudents()
        );
    }
}

Die alte Klasse musste nicht verändert werden.

Der Adapter sorgt dafür, dass das neue Interface trotzdem verwendet werden kann.
